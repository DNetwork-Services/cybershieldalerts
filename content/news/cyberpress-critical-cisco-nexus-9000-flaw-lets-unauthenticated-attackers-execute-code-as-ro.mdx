Cisco has disclosed a critical remote code execution vulnerability in Nexus 9000 Series Switches equipped with Silicon One ASICs that could allow unauthenticated attackers to run arbitrary code with root privileges. Tracked as CVE-2026-20212, the flaw received a CVSS v3.1 score of 9.8 out of 10 and is documented in Cisco advisory cisco-sa-n9k-s1-rce-EH8dEtr. Cisco published the final advisory on September 2, 2026, and released software updates and temporary mitigations for affected customers. Critical Cisco Nexus 9000 Flaw The vulnerability exists in the Silicon One integration used by specific Cisco Nexus 9000 platforms. According to Cisco, TCP ports 43210 and 43211 are accessible through the default Layer 3 virtual routing and forwarding (VRF) instance. An unauthenticated remote attacker could connect to an exposed affected switch and send specially crafted input to these ports. Successful exploitation could result in attacker-supplied code being executed with root-level privileges on the device. Root access would give an attacker extensive control over the impacted network switch, potentially enabling configuration manipulation, credential collection, traffic interception, disruption of data-center connectivity, or use of the compromised device as a foothold for further network attacks. Cisco also warned that exploit attempts could crash the S1HAL process, potentially causing the affected device to reload. In data-center environments where Nexus switches support critical workloads, an unexpected reload could create a denial-of-service condition and interrupt applications, storage access, or east-west network traffic. The issue affects Nexus 9000 Series Switches containing a Silicon One ASIC. Cisco listed the following affected product identifiers: N9324C-SE1U, N9348Y2C6D-SE1U, N9364E-SG2-O, N9364E-SG2-Q, N9396T12C-SE1, N9348Y12C-SE1, N9396Y12C-SE1, N9336C-SE1, N9K-C9804, and N9K-C9808. Administrators can determine whether a switch matches an affected model by running the show module command from the NX-OS command-line interface and checking the reported model identifier. Cisco noted that only the Nexus 9000 products specifically named in the advisory are known to be vulnerable. Notably, Cisco confirmed that Nexus 9000 switches not listed as affected are not vulnerable. The company also said Nexus 9000 Series Fabric Switches running in Application Centric Infrastructure (ACI) mode are unaffected. Other confirmed unaffected product families include Nexus 3000 and Nexus 7000 switches, MDS 9000 switches, Cisco Firepower appliances, Secure Firewall appliances, and several UCS Fabric Interconnect models. Cisco has released fixed NX-OS software versions that customers can identify with the Cisco Software Checker. The tool allows organizations to enter their platform and installed software release to identify relevant advisories and the earliest available fixed release. For organizations unable to immediately patch, Cisco recommends deploying infrastructure access control lists (iACLs) to restrict management and control-plane traffic destined for vulnerable switches. Alternatively, administrators can configure rules that explicitly deny TCP traffic targeting locally configured device IP addresses on ports 43210 and 43211.
