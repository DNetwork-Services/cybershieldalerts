Microsoft will make passkeys the default authentication experience in Entra ID beginning September 1, 2026, while retiring its native SMS and voice multifactor authentication delivery on February 1, 2027. According to Microsoft, the move reflects a broader push to eliminate phishable credentials as enterprises scale cloud and AI adoption. Under the new policy, Entra tenants with users enabled for SMS or voice authentication will have those users automatically enabled for passkeys in the Authentication Methods Policy. Microsoft Entra ID to Retire SMS and Voice MFA During a subsequent sign-in that requires MFA, eligible users will be prompted to register a passkey. Microsoft will set the Registration Campaign to the Microsoft Managed state and automatically target affected users. The company describes passkeys as phishing-resistant credentials based on cryptographic key pairs rather than shared secrets such as passwords or one-time SMS codes. They are designed to resist common account-takeover techniques, including credential phishing, SIM-swapping, and replay attacks. Entra ID supports both synced and device-bound passkeys. Synced passkeys are stored in credential managers such as iCloud Keychain or Google Password Manager and can sync across users&#8217; devices. Device-bound passkeys remain tied to a specific platform or authenticator, including Windows Hello for Business, Microsoft Authenticator, Entra Passkey on Windows, and FIDO2 hardware security keys. Microsoft-provided SMS and voice services will be fully retired on February 1, 2027. After that date, organizations that still need telecom-based MFA must use a customer-managed provider available through the Microsoft Security Store. Microsoft plans to publish provider information beginning September 18, 2026, with customer selection and configuration expected to become available from October 30, 2026. The retirement has operational consequences for organizations that delay migration. Users relying exclusively on SMS or voice will encounter a blocking passkey-registration prompt after February 1, 2027. They must enroll a passkey before continuing to access their accounts. Microsoft states that this enforcement will apply to all tenants and has no opt-out option. Administrators should first identify users who remain enabled for SMS or voice in either the Entra Authentication Methods Policy or legacy MFA settings. Microsoft has published a PowerShell-based usage analyzer for this purpose that requires Global Reader, Authentication Policy Administrator, or Security Reader permissions. Organizations are advised to adopt a staged rollout. This includes enabling FIDO2 passkeys, creating security groups for affected users, launching a registration campaign, and delivering targeted communications. Users can initially snooze the enrollment prompt indefinitely, so organizations should pair technical configuration with clear deadlines and end-user guidance. Microsoft does offer a temporary mechanism to postpone the automatic passkey enablement and registration campaign between September 1, 2026, and February 1, 2027. Using Microsoft Graph beta, administrators with Policy.ReadWrite.AuthenticationMethod permission can set the passkeyDynamicMigration opt-out property to true. That delay does not extend the SMS and voice retirement deadline. Enterprises with regulatory or operational requirements for an out-of-band telecom channel must evaluate and deploy a customer-managed provider before February 2027. For most users, however, Microsoft’s recommended path is a migration to passkeys, Windows Hello, or another phishing-resistant authentication method before SMS and voice access creates sign-in disruption.
