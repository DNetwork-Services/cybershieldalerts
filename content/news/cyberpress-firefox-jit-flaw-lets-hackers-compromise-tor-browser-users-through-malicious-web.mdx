A single malicious webpage is enough to compromise Tor Browser users running an unpatched build, following the disclosure of CVE-2026-10702, a high-severity Firefox JavaScript engine vulnerability that researchers at Nebula Security successfully exploited against Tor Browser. Mozilla resolved the flaw in Firefox 151.0.3 on June 2, 2026, and the Tor Project subsequently integrated the fix into updated browser releases, making prompt updates the primary defense for privacy-focused users. The vulnerability stems from a Just-In-Time (JIT) miscompilation bug inside Firefox&#8217;s SpiderMonkey JavaScript engine. Because Tor Browser relies on Firefox as its underlying framework, vulnerabilities in the core engine directly expose Tor users to drive-by exploitation. Hackers Compromise Tor Browser Users Unlike social engineering attacks that require manual downloads or explicit permission prompts, this flaw enables arbitrary code execution within the browser&#8217;s renderer process simply by rendering malicious web content. Following a chain that runs from the malicious webpage through the SpiderMonkey JavaScript engine into a JIT optimization error, a resulting use-after-free condition, and ultimately full renderer process compromise. This poses a severe threat to anonymity networks, since compromising the renderer process breaks browser-level compartmentalization and opens potential vectors for identity exposure. And the Tor Browser is also affected by CVE-2026-10702.Update your Tor! pic.twitter.com/5TMQkRPAjN&mdash; Nebula Security (@nebusecurity) July 28, 2026 The underlying flaw lies deep within SpiderMonkey&#8217;s Ion/Warp JIT compilation pipeline and surfaces across several related optimization passes. These include flawed assumptions in how the engine handles array and object keys during Object.keys() processing, errors during implicit property lookups such as length, name, or prototype during lazy property resolution, and a deeper alias analysis mistake in which memory-allocating operations are incorrectly treated as harmless reads. When SpiderMonkey lazily resolves function properties, full property buffers require new memory allocations, but the JIT optimizer may continue referencing the old, now-stale property buffer. According to CSN, this stale pointer reuse creates a usable use-after-free (UAF) condition, allowing attackers to construct address disclosure and fake object primitives, the key building blocks needed for a complete renderer compromise. The disclosure and patch cycle progressed rapidly following initial discovery. Nebula Security reported the zero-day flaw to Mozilla on May 20, 2026, and Mozilla confirmed the root cause the same day. Mozilla then released Firefox 151.0.3 on June 2, 2026, to resolve the JIT flaw, and the Tor Project followed on July 20, 2026, with Tor Browser 15.0.19, which included the necessary upstream fixes. For privacy-conscious users, the operational takeaway is clear: underlying browser vulnerabilities can bypass network-level anonymity safeguards if the software remains unpatched. Installing official Tor Browser patches immediately closes drive-by exploitation vectors, while keeping up with upstream Firefox security updates ensures ongoing protection against browser engine exploits.
