Security researchers have uncovered the first documented malware campaign specifically targeting Android-based automotive head units, attributing the operation with high confidence to MoYu Group, a threat actor tied to the notorious BADBOX botnet. The discovery marks a significant escalation as botnet operators expand beyond smartphones, smart TVs, and set-top boxes into in-vehicle infotainment systems, echoing trends seen in other covert malware campaigns infiltrating connected smart hardware. BADBOX-Linked MoYu Hackers Build Android Proxy Botnet While monitoring Android threats in June 2026, researchers flagged a suspicious application that installed like a normal user app but had no user interface whatsoever, a red flag suggesting it was reaching devices without user consent, according to Kaspersky&#8217;s Securelist research report. Investigation traced the infection to DoFun head unit firmware, where a legitimate system app called TWCore, responsible for analytics and software updates, was abused as the delivery mechanism. TWCore receives update instructions via an MQTT broker hosted on cardoor[.]cn. A Boolean flag named installNotExists allows the broker to push and silently install APKs that were never present on the device, completely bypassing the normal update-check logic. Kaspersky notified the vendor, which has since reported fixing the issue. Automotive Head Unit Infection Chain (Image Source: securelist.com) The malware unfolds through a multi-stage architecture. Stage 1, dubbed JarService, is a UI-less dropper that decrypts XOR-encrypted blocks to load a stage 2 payload via reflection, operating similarly to evasive malware droppers built to bypass runtime inspection. Stage 2 acts as a loader, beaconing device details to a command-and-control server and retrieving a stage 3 payload URL. Stage 3, tracked internally as BillingMain, functions as a clicker and reverse-proxy loader, checking in every 90 minutes with device fingerprint data and pulling configuration updates or one of nine supported commands, including http, web, loadlib2, and deeplink. The most consequential command deploys &#8220;zhima,&#8221; a reverse proxy module that was independently identified around the same time by Nokia Deepfield&#8217;s Emergency Response Team running on TV set-top boxes, confirming the campaign&#8217;s core objective: building a monetizable proxy botnet alongside ad-fraud clicker functionality. Researchers linked the campaign to MoYu Group after finding a thread in the stage 2 loader named mosdk-host-loader, which connected to a malicious set-top box app containing a service literally named AdmoyuService. Infrastructure overlap, including a zhima admin panel at admin.uipoxy[.]com featuring invite-code registration, and shared authentication API patterns across residential-proxy-linked domains tied to PXYEDGE and ProxyForU, further cemented the attribution. Full indicators of compromise, including hashes for JarService, the loader, the clicker, and zhima variants, along with C2 domains such as kshahnd[.]sbs and mdsjhd[.]sbs, provide network defenders with actionable intelligence against these malicious botnet operations. Despite takedown efforts against BADBOX, affiliated actors continue diversifying delivery methods, from pre-installed backdoors to compromised IPTV builds, and now legitimate firmware update pipelines. Automotive head units, often internet-connected via SIM cards for navigation and updates, represent a largely unprotected new frontier that vendors and fleet operators must now factor into their threat models.
