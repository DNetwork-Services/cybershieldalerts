A newly disclosed zero-day vulnerability in GeoServer is drawing urgent attention after security researchers reported that an unauthenticated SQL injection could allow attackers to target exposed geospatial servers and, under specific conditions, achieve remote code execution. The vulnerability reportedly affects GeoServer’s handling of the jsonArrayContains function within OGC filter processing. GeoServer is widely used to publish geospatial data through standards-based services, including Web Map Service, Web Feature Service, and Web Coverage Service. These services can accept Common Query Language and filter expressions that are ultimately translated into database queries. If attacker-controlled input is incorporated into that query construction without adequate parameterization, an attacker may be able to alter the underlying SQL command. GeoServer Zero-Day SQL Injection The issue was disclosed publicly by a researcher using the handle @q1uf3ng, who described it as an unauthorized SQL injection vulnerability related to jsonArrayContains. The researcher further claimed that remote code execution could be obtained in deployments using an sa database configuration. At publication time, no CVE identifier or vendor patch had been publicly confirmed, leaving defenders to assess exposure based on their GeoServer version, datastore settings, and database permissions. Proof-of-concept material accompanying the disclosure shows how malformed filter input can produce backend error messages and different response types. This can be valuable to an attacker because it helps distinguish unsuccessful requests from requests that reach a vulnerable SQL-generation path. The reported technique first identifies a usable database column, then attempts stacked SQL injection. In the demonstration, the final stage uses a PostgreSQL server-side capability to write the output of a program executed against the database to a temporary file. However, SQL injection should not be treated as automatically equivalent to full server compromise. The practical outcome varies significantly by environment. A restricted database user may limit an attacker&#8217;s ability to expose, modify, or disrupt services. A highly privileged database account, particularly one that can invoke dangerous database-side features, may enable escalation beyond the database to operating-system command execution. Database type, version, extensions, deployment architecture, container configuration, and the operating-system permissions assigned to the database service all shape the real-world risk. Researchers have already observed signs of active exploitation attempts. The disclosure also recalls GeoServer’s prior history with OGC filter SQL injection flaws. In 2023, GeoServer issued an advisory for CVE-2023-25157, which included jsonArrayContains among several vulnerable filter functions. That issue affected certain GeoServer versions and datastore scenarios involving PostGIS or Oracle, and was addressed in later releases. The current report should not yet be assumed to be identical to that vulnerability; it may be a separate flaw or a regression. Organizations operating GeoServer should immediately reduce unnecessary internet exposure, place services behind access controls where possible, and review logs for anomalous CQL filters, repeated malformed requests, and database parsing errors. GeoServer database accounts should follow the principle of least privilege and not retain permissions that can invoke administrative or operating-system-level functionality.
