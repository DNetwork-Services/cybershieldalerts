Microsoft SharePoint Server administrators are being urged to apply updates immediately after researchers observed attackers probing a two-vulnerability chain that could deliver unauthenticated remote code execution against internet-exposed on-premises SharePoint Server. The flaws, CVE-2026-55040 and CVE-2026-63520, affect SharePoint Server Subscription Edition, SharePoint Server 2019, and SharePoint Enterprise Server 2016. The urgency increased after Defused reported seeing probes targeting the complete exploit chain in its honeypot infrastructure. The firm said attackers exploited the JWT authentication bypass in CVE-2026-55040, then conducted extensive enumeration of administrator accounts and probed the Business Data Catalog attack surface associated with CVE-2026-63520. Microsoft SharePoint Flaws Defused has not observed code execution in these attempts, but the activity shows adversaries are actively assessing exposed servers for full compromise. The observed sequence follows VulnCheck’s publication of a detailed exploitation path that joins the two bugs. CVE-2026-55040, rated 9.1 under CVSS v3.1, is a critical authentication-bypass issue in SharePoint’s JSON Web Token handler. Its exploitability depends on security settings, including RequireSignedTokens, which is disabled by default. An attacker who knows a user’s SID or UPN can forge a JWT. That forged token can bypass SharePoint’s validation checks and let an unauthenticated remote actor impersonate the chosen account, including a privileged administrator, without legitimate credentials. CISA added CVE-2026-55040 to its Known Exploited Vulnerabilities catalog on August 18, confirming active exploitation. The latest honeypot telemetry indicates operators are now evaluating whether vulnerable environments also permit the publicly documented code-execution chain. CVE-2026-63520, with a CVSS v3.1 score of 8.1, targets SharePoint’s Business Connectivity Services component, which supports connections between SharePoint applications and external business data. BCS normally limits object creation to classes named in the BCSAllowedTypeNames allow list. Before Microsoft’s fix, however, an attacker could supply an arbitrary class name within a malicious Business Data Connectivity model. VulnCheck found that invoking System.Web.UI.LosFormatter could instantiate a deserialization gadget and eventually execute arbitrary server-side code. Organizations should treat the findings as one urgent exposure, rather than two unrelated patching issues. Microsoft has issued security updates for every affected on-premises version, while SharePoint Online is not affected. Censys identified roughly 329,000 SharePoint instances on August 25, including about 21,000 on-premises systems exposing version information. Administrators should install both updates without delay, reduce direct internet exposure wherever possible, and verify that token signing protections are enabled. Teams should also review authentication logs for anomalous JWT use, investigate unexpected administrator enumeration, and examine Business Data Catalog requests for suspicious models or class names.
