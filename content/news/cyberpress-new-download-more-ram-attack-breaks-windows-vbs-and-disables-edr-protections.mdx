A newly disclosed Windows attack technique dubbed “Download More RAM” can undermine Virtualization-Based Security (VBS), bypass Hypervisor-Protected Code Integrity (HVCI), and disable endpoint defenses including Microsoft Defender and third-party EDR products. Documented by USENIX, the attack does not exploit a conventional Windows kernel vulnerability. Instead, it targets an overlooked weakness in certain consumer DDR4 and DDR5 memory modules: writable Serial Presence Detect (SPD) configuration data. SPD data tells a system’s firmware how much memory is installed and how it is organized. If the SPD EEPROM is insufficiently write-protected, an attacker with local administrator privileges can alter the reported geometry of a DIMM, causing the system to believe that more RAM is present than is physically present. New “Download More RAM” Attack Breaks Windows VBS That incorrect configuration causes memory aliasing: different physical addresses map to the same underlying DRAM locations. The researchers call the technique “Download More RAM” because the machine effectively reports double the capacity of an affected memory stick, even though no additional physical RAM is installed. Windows Virtual Trust Levels Visualised (source: usenix) Unlike earlier BadRAM-style research, the demonstrated attack is software-only and does not require attackers to remove, modify, or reinstall memory modules. The impact is severe because aliased memory can expose the raw physical memory space that VBS is intended to isolate. Windows VBS relies on Hyper-V and Virtual Trust Levels to separate the ordinary Windows kernel from sensitive components such as the Secure Kernel, Credential Guard, and isolated user-mode processes. In the USENIX demonstration, memory aliasing enabled access to regions that should remain inaccessible even to a privileged Windows administrator. The practical attack chain is complex, but its security outcome is straightforward. After creating the alias, the researchers stabilized Windows by preventing the operating system from using the affected upper memory region. They then used legitimate signed tooling to inspect the aliased region and a RAM-disk mechanism to make constrained changes to memory. This allowed them to patch the Secure Kernel Code Integrity library, skci.dll, disabling checks that enforce Microsoft’s vulnerable-driver blocklist. Once those checks were bypassed, previously blocked but legitimately signed vulnerable drivers could be loaded. Such drivers can provide powerful physical memory read-and-write primitives, effectively circumventing the boundaries enforced by VBS and HVCI. The USENIX paper states that this creates access to the system’s complete physical memory and invalidates isolation guarantees intended to protect the Windows kernel, Secure Kernel, and Hyper-V-managed components. Overview of Download More RAM (Source: usenix) In proof-of-concept case studies, the team used the technique to disable Windows Defender protections and demonstrated impact against Sophos Intercept X configurations. They also showed that VBS-protected enclave code could be read and modified, and that kernel-level game anti-cheat systems including Riot Vanguard, BattlEye, and Easy Anti-Cheat could be affected. The researchers further developed a one-click automation workflow that requires administrator privileges but requires no further user interaction after execution. The affected hardware exposure is not universal. The research surveyed selected consumer modules and identified unprotected SPD configurations in product lines from Corsair, G.Skill, and ADATA. The authors stress that this was not an exhaustive market survey, so protection may vary by product line and model. Microsoft assigned CVE-2026-23670 and shipped mitigation in its April 2026 Windows security update. The update prevents the Secure Boot-compatible removememory boot parameter from being used in the attack path demonstrated. However, the researchers caution that the underlying ability to create aliases on writable-SPD DIMMs remains relevant, and alternate system-stabilization approaches could revive the technique. For defenders, immediate priorities are applying current Windows updates, verifying Secure Boot status, reviewing BIOS options that block SPD writes, and tracking RAM-vendor guidance on SPD write protection.
