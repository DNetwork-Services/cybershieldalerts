A newly disclosed flaw in Unitree’s G1 humanoid robot could allow an attacker standing nearby to obtain unauthenticated remote code execution as root via Bluetooth Low Energy (BLE). The research, dubbed UniBLEed, targets the robot’s Locomotion PC, a Linux-based system that supports safety-critical operations including motors, cameras, audio, and voice. The Bluetooth attack chain, tracked as CVE-2026-76640, begins with GATT characteristic 0xFFE2. The interface accepted writes using only basic WRITE permissions, enabling a device within radio range to communicate with the robot without BLE pairing or authentication. Unitree G1 Humanoid Robot Flaws A plaintext bootstrap request then returned a robot-specific AES-128 key inside an RSA-encrypted response. Although RSA wrapping would normally prevent recovery of that secret, Boschko found that Unitree’s /device/bindExtData cloud API could decrypt the returned material and reveal the plaintext AES key to any authenticated Unitree account. Crucially, the endpoint reportedly failed to check whether the submitted serial number belonged to that account. An attacker near a target could therefore retrieve a secret associated with the robot’s BLE version 3 provisioning and Wi-Fi setup. Armed with the key, the researcher accessed protected BLE functions and supplied a 121-byte pre-shared key that triggered an insecure Wi-Fi fallback in wpa_connect.sh. Attacker-controlled content entered an unquoted heredoc, allowing manipulation of the generated wpa_supplicant configuration and connection to a rogue hotspot. The final stage abused btgatt-server, a Bluetooth daemon running as root. Boschko wrote a 1,050-byte value through a 500-byte wifi_ssid buffer, then paired the overflow with an information leak that weakened address-space layout randomization. The exploit changed event-loop cleanup state so that system() executed an attacker-selected command with root privileges. While the service subsequently crashed, the report says that a background shell continued to run. CVE-2026-76639 describes a separate root-RCE route involving the chat_go AI service and bashrunner. A path traversal flaw in a knowledge-base upload process allowed a file to land in bashrunner’s whitelist directory. Because the service constructs that whitelist at import and uses shell execution rules that ignore file extensions, a malicious file could be executed as root. The bug also aided address disclosure in the BLE chain. Unitree reportedly verified both chains during coordinated disclosure and updated the key-retrieval flow to ensure an account matches the robot’s ownership before plaintext is returned. Boschko said the fixes addressed most, if not all, of the reported weaknesses, but emphasized that the analysis reflects tested builds rather than necessarily the latest G1 software. The issues were reproduced on four G1 robots, earning the researcher $5,000 in total bug bounties. Operators should install Unitree updates, restrict physical and Bluetooth proximity, audit cloud account access, and assume that unpatched robots may expose credentials or allow control of essential functions. The findings underscore why radio provisioning, cloud authorization, and safety-critical services require strict separation by design.
