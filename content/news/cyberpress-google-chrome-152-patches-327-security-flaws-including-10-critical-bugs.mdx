Google has released Chrome version 152 for Windows, macOS, and Linux, addressing 327 security vulnerabilities, including 10 flaws rated Critical. The Stable channel update is rolling out as version 152.0.7977.64 for Linux and version 152.0.7977.64/.65 for Windows and macOS. The update is significant because it resolves a broad set of memory-safety, authorization, input validation, and information disclosure issues across Chrome’s graphics stack, browser interface, JavaScript engine, networking components, Safe Browsing, WebRTC, and Chromecast functionality. Most of Chrome 152’s Critical flaws involve use-after-free conditions, a memory-corruption category that occurs when software accesses memory after it has been freed. Google Chrome 152 Patches 327 Security Flaws Depending on the affected component and exploit conditions, these flaws could cause crashes, information exposure, or arbitrary code execution. The most notable externally reported issue is CVE-2026-79282, a Critical use-after-free vulnerability in ANGLE. ANGLE is Chrome’s graphics translation layer, responsible for translating graphics API calls across platforms. Since it processes complex graphics content supplied by websites, it has long been considered a high-value browser attack surface. Google awarded the researcher, Goodluck, $25,000 for reporting the vulnerability. Chrome 152 also addresses Critical issues in Aura, Chromecast, Views, Safe Browsing, and mobile functionality. The release includes an improper input-validation flaw in Chromecast and a use-of-uninitialized-variable issue affecting mobile code. ANGLE received fixes for out-of-bounds reads and writes, buffer overflows, and other memory-corruption conditions. These flaws are especially relevant because graphics-rendering code processes attacker-controlled content embedded in websites and advertisements. Google also fixed High-severity type-confusion bugs in V8, Chrome’s JavaScript and WebAssembly engine. Type confusion occurs when a program incorrectly interprets an object as a different data type, potentially allowing an attacker to read or write memory in unintended ways. V8 vulnerabilities are regularly examined by security researchers because JavaScript can be delivered directly through a malicious or compromised webpage. The remaining Medium- and Low-severity fixes address Chrome networking, Site Isolation, DevTools, Web Authentication, USB, WebXR, file handling, Extensions, Service Workers, permissions, payments, media, DOM, GPU, Skia, WebView, and enterprise features. Google said it will restrict certain vulnerability details and bug links until most Chrome users have updated, a standard practice intended to reduce the risk of attackers weaponizing public technical information against unpatched systems. Administrators should deploy Chrome 152 across managed Windows, macOS, and Linux endpoints as soon as possible. Users can verify their installed browser version by visiting chrome://settings/help, which initiates Chrome’s update check. A restart is required to activate the patched version.
